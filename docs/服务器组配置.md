# 服务器启动与动态发现

## 类型连接配置

`code/server/config/server.yaml` 是总入口，声明 `include: [ops, process]`、`environment`、`loggingMinimumLevel` 和 `runDirectory`。include 是应用层约定：读取入口同目录下对应的 `.yaml`，各文件独立解析后合并顶层字段；重名、缺失文件、循环 include、非法文件名会失败。锚点和别名只在单文件内复用值，不能跨文件引用。

`process.yaml` 的 `connections` 定义主动连接类型，例如：

```yaml
connections:
  Router: []
  DBMgr: [Router]
  Scene: [Router]
  Login: [Router]
  Base: [Router, DBMgr]
  Profile: [Router]
  GM: [Router]
  Gate: [Login, Base]
```

配置必须包含所有已知类型，不允许未知类型、重复键或目标、自连、双向拨号和循环依赖。Gate 只提供玩家入口，不可作为进程间主动拨号目标。每对实例只由配置指定的一端拨号，连接本身可双向通信。类型关系在进程启动时读取；动态变化的是实例成员，不是这份启动配置。

App 从统一入口加载一个 `ServerConfiguration`，它完成核心配置与拓扑校验并持有 `ServerGroup`。配置实例通过 `GetDialTargets`、`Dials` 和 `ArePeers` 查询类型关系，其 `Group` 通过 `GetStartupMinimum(ProcessType)` 查询首次连接门槛；节点通过构造函数接收这些共享配置。数量不展开固定名单，也不限制合法实例编号或最大连接数。

## 按类型启动

```powershell
.\tools\scripts\StartAll.bat       # 按 process.yaml 的 processes 数量逐个调用类型脚本
.\tools\scripts\StartRouter.bat    # 单独新增一个 Router
.\tools\scripts\StartDBMgr.bat
.\tools\scripts\StartBase.bat
.\tools\scripts\StartScene.bat
.\tools\scripts\StopAll.bat        # 正常停止脚本组，超时不强退
.\tools\scripts\KillAll.bat        # 强制结束脚本组
```

单类型脚本每次启动一个进程；启动多个 Scene 就多次执行 `StartScene.bat`。`StartAll` 根据启动数量补齐本轮缺失槽位。启动器优先读取 `TGAME_SERVER_CONFIG`，缺省使用源码 `code/server/config/server.yaml`。App 只接收类型参数，从启动器设置的 `TGAME_SERVER_CONFIG` 直接读取源配置，不保存独立配置快照。`runDirectory` 是相对工作目录的运行材料路径：脚本以它作为运行组父目录，桌面控制台使用自己的会话目录；两者都创建本轮目录并通过 `TGAME_SERVER_RUN_DIRECTORY` 传给进程，不回写源配置。各角色只启动进程基础框架，不初始化存储。

PowerShell 7 启动脚本复用引擎配置源码及 YamlDotNet。新工作区先执行 `dotnet restore code/server/engine/TGame.Server.Engine.csproj`，确保 NuGet 依赖可用。

宿主要求环境名、相对运行目录、合法进程数量/拓扑，以及 `zooKeeperOptions` 的地址、发现根路径、worker 根路径和超时；`loggingMinimumLevel` 缺省为 `INFO`。MongoDB、Redis 不在基础框架启动时建立连接，独立存储工具使用时校验字段与凭据。配置只保存密码环境变量名，密码由使用方从环境读取。

宿主先创建日志，通过 `ServerConfiguration.LoadSelected()` 加载、绑定并校验完整核心配置，再构建一个 IoC 根容器。只注册这一个配置实例及其持有的 `Group`、`ZooKeeperOptions`、`Identifiers`，ZK、ID 和节点注册为共享服务，依赖通过构造函数传入。ZooKeeper 代理构造不连接，宿主显式初始化会话，用临时节点从 1 开始抢占空闲编号，例如 `/tgame/test/server-Scene1`，随后初始化 ID 生成器并解析节点。只有创建明确返回节点已存在才尝试下一个；创建结果不确定时终止共享会话。编号由 `ServerProcess.FormatName` 格式化，空地址占号节点不参与拨号。

监听启动后持续发现主动目标；每种主动目标类型的已握手不同实例数同时达到 `process.yaml` 的 `processes` 对应数量后，完成 `FirstLinks`，向已占用的节点发布监听地址并记录 `PROCESS_READY`。数量为 `0` 的类型不阻塞首次启动。依赖根节点（默认 Router）无需等待入站实例，可直接就绪并发布。接收方只接受本地已就绪时的连接，主动方可以尚未发布地址，但必须已占用合法的临时身份。

正常退出先取消并等待后台工作、停止监听，再异步释放容器中的 ID 生成器和 ZooKeeper 会话，最后释放日志；崩溃后由 ZK 在会话过期时删除节点。空闲编号可复用，存活实例不重新编号。编号标识一次运行中的进程实例，不是永久业务身份。会话失效继续停止进程，不能继续使用已失效的编号和雪花 worker 租约。

## 进程连接与就绪

持续发现并尝试连接所有符合主动目标类型的实例。首次启动时，`ServerNode.Ready` 与 `FirstLinks` 要求每种主动目标类型的已握手不同实例数达到配置门槛；正在拨号或尚未完成握手的连接不计数，入站连接也不能替代主动依赖。没有实体初始化或注册确认阶段。

- Base 按 `Router` 和 `DBMgr` 各自的配置数量等待，不等待 Gate。
- Scene 按 `Router` 的配置数量等待；例如 `Router: 2` 时至少连接两个不同 Router 实例。
- Gate 按 `Login` 和 `Base` 各自的配置数量等待。
- Router 无主动目标，可直接就绪。

`FirstLinks` 只完成一次，`Ready` 直接表示它是否已成功完成。门槛为 `0` 的类型不阻塞首次启动，但仍持续发现并连接。例如 `Router: 2` 首次要求两个 Router，完成后即使两个 Router 全部断开也保持就绪，仍接受入站连接并持续重连。对端重新拉起后恢复对应通信，不重新要求首次数量。未连接实例的 RPC 返回 `Unavailable`，断线上的待处理 RPC 失败；保持就绪不代表所有依赖当前可用。

首次达标不会结束 ZooKeeper Watch 或连接维护。新增 Router 尚未连接不会使已有成功连接失效，但仍会继续拨号；数量不是连接上限，后续发现的所有匹配实例都会继续连接。成员退出、地址变化或同名重建仍按快照收敛。

基础 RPC 使用 `ServerNode.CallPeerAsync` 向已连接的实例直接发送请求，保留请求关联、错误、超时和取消。当前未接入业务处理入口，收到请求返回 `Unimplemented`；Router 不执行实体路由，启动就绪也不代表已提供游戏业务。

## ZooKeeper 成员变化

引擎读取完整成员快照并设置 Watch，通知后重新读取和续订。复用 Watcher 并合并通知，避免稳定成员的监听对象累积。记录包含类型、规范实例名、监听地址及节点创建代次；成员离开、地址变更、同名节点重建都会取消旧连接维护并按新快照收敛。非法成员记录被记录并忽略，不能终止其他健康成员的发现。

目前端点仍限本机回环地址；跨机器地址发布不在本次范围。当前框架只处理进程成员与连接变化；后续接入业务时，需另行设计业务状态迁移与排空。

## 初始启动数量与首次连接门槛

`code/server/config/process.yaml` 的 `processes` 同时定义控制台初始启动数量和对应类型的首次连接门槛，必须包含所有类型，数量为非负整数，整组至少一个进程。`Router: 2` 表示控制台初始启动两个 Router，也表示依赖 Router 的进程首次至少连接两个 Router；数量不限制这些进程后续连接更多实例。`Router: 0` 表示控制台不初始启动 Router，依赖它的进程不因 Router 缺席而阻塞，但仍发现并连接后来出现的 Router。

App 构建时将三份 YAML 复制到输出 `config/`。启动器直接传递选中的源入口路径，不把配置复制到本轮可执行目录，也不保存展开后的 YAML。本轮运行目录通过 `TGAME_SERVER_RUN_DIRECTORY` 传递；每个进程启动时加载源配置一次，运行期间不热重载。脚本的 `current` 指针及互斥锁固定保存在 `logs/tools/server-scripts/`，指针记录本轮相对运行目录。补起继续使用本轮可执行文件和运行目录，并读取源配置；停止只依赖进程记录，不要求源配置有效。

控制台启动时传类型，按 PID 与启动时间读取实际获配实例名，并按 `ProcessReady`（`PROCESS_READY`）事件判断启动就绪。启动槽位只用于本地进程恢复，不被当作 ZK 身份；日志页签显示实际实例。停止写入精确进程生命周期的标记，避免实例编号复用导致停止错对象。控制台只恢复带有 `dynamic-discovery` 标记的运行组，不再兼容旧静态身份快照。遇到旧组时，先用旧版控制台停止整组，再删除 `logs/tools/server-console/current` 会话指针，重新打开控制台并编译启动。

手动停止可写 `stop-Scene1`（按当前实例）或运行目录的 `stop`（整组）。使用 `stop-Scene1` 后重新使用同一运行目录启动时，应删除已处理的手动停止标记。控制台自己的精确停止标记不影响后来的同名实例。

## 日志和验证

服务器环境 YAML 通过 `loggingMinimumLevel` 控制本次运行的最低日志级别，支持 `DEBUG`、`INFO`、`ERROR`。本地测试配置 `code/server/config/server.yaml` 默认使用 `DEBUG`；其他配置省略此项时使用 `INFO`。

```yaml
loggingMinimumLevel: DEBUG
```

- `DEBUG`：测试排查所需的请求收发和服务发现明细；独立存储工具可记录缓存读取细节。
- `INFO`：监听、连接建立、初始化及进程就绪等普通运行记录。
- `ERROR`：进程或初始化失败、RPC 异常、连接丢失等需要关注和排查的问题。

日志管理器由宿主在配置加载前通过 `new GameLog()` 创建，将同一个对象注册到 IoC 容器；调用方接收实例后使用 `log.Debug` / `Info` / `Error`。ZooKeeper 占用实例身份后通过 `log.OpenServer(process)` 开启文件日志。这个已有实例由宿主显式释放，容器不接管它的释放；容器构建、启动或清理失败仍可记录日志，最后才关闭日志文件。重复打开文件和释放后的调用会明确报错。

每条 JSON 日志包含大写 `level` 字段。最低级别为 `INFO` 时不写入 DEBUG；为 `ERROR` 时只写入 ERROR。过滤在序列化及写文件前执行，未打开日志文件时的标准输出也使用相同过滤规则。级别由运行配置决定，与 Debug/Release 编译模式无关。启动配置加载失败仍会记录 ERROR。

日志级别在进程启动时读取，修改后重启进程才能应用。当前控制台依赖 INFO 级别的 `PROCESS_READY` 判断启动就绪，因此最低级别设为 `ERROR` 时无法准确展示就绪状态。

例如 Base2 的日志写入 `logs/server/Base2Server/`，记录中 `role` 为 `Base`，`instance` 为 `Base2`。日志文件以 PID 和进程启动 UTC ticks 定位，不再使用 runId。`stop-Base2` 只停止 Base2，`stop` 停止整组。

以下为当前操作入口，不表示本次文档更新已经执行这些检查。按改动选取必要的小范围检查，避免重复运行同一覆盖范围。

```powershell
# 基础节点、握手、RPC 与就绪检查；--node 与 --engine 同义，无参数也运行 engine。
dotnet run --project code/tests/engine/TGame.EngineTests.csproj -- --engine

# 动态拓扑与真实回环 gRPC，不依赖外部服务。
dotnet run --project code/tests/engine/TGame.EngineTests.csproj -- --dynamic-topology
dotnet run --project code/tests/engine/TGame.EngineTests.csproj -- --discovery-links

# IoC 生命周期、日志与配置；按本次改动选择。
dotnet run --project code/tests/engine/TGame.EngineTests.csproj -- --ioc
dotnet run --project code/tests/engine/TGame.EngineTests.csproj -- --logging
dotnet run --project code/tests/engine/TGame.EngineTests.csproj -- --configuration
dotnet run --project code/tests/engine/TGame.EngineTests.csproj -- --yaml-configuration

# 控制台就绪状态、身份跟踪、恢复和精确停止，不启动服务器组。
dotnet run --project tools/server-console/tests/ServerConsole.Check.csproj -- --state-only
```

外部 ZooKeeper 或完整控制台联调须另行说明范围、预计耗时并获得明确同意；准备本地 SSH 隧道后再运行所需入口：

```powershell
$env:TGAME_SERVER_CONFIG = (Resolve-Path code/server/config/server.yaml).Path
dotnet run --project code/tests/engine/TGame.EngineTests.csproj -- --registry
dotnet run --project code/tests/engine/TGame.EngineTests.csproj -- --startup-publication
pwsh -NoProfile -File tools/scripts/powershell/Test-ServerConsole.ps1 -Configuration code/server/config/server.yaml
```
