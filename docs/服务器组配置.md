# 服务器启动与动态发现

## 类型连接配置

`code/server/config/connections.json` 是服务运行时的类型连接规则，复制到构建输出的 `config/`。每个键是本进程类型，数组是它主动连接的类型。例如：

```json
{
  "Router": [],
  "DBMgr": ["Router"],
  "Scene": ["Router"],
  "Login": ["Router"],
  "Base": ["Router", "DBMgr"],
  "Profile": ["Router"],
  "GM": ["Router"],
  "Gate": ["Login", "Base"]
}
```

配置必须包含所有已知类型，不允许未知类型、重复键或目标、自连、双向拨号和循环依赖。Gate 只提供玩家入口，不可作为进程间主动拨号目标。每对实例只由配置指定的一端拨号，连接本身可双向通信。类型关系在进程启动时读取；动态变化的是实例成员，不是这份启动配置。

`ServerConfiguration.Load(...)` 加载并校验独立配置实例，通过 `GetDialTargets`、`Dials` 和 `ArePeers` 查询类型关系；节点从构造函数接收这份只读配置。服务器运行时不读取 `processes.json`，不再通过数量展开固定名单或限制合法实例编号。

## 按类型启动

```powershell
dotnet build code/server/app/TGame.Server.csproj
$env:TGAME_SERVER_CONFIG = (Resolve-Path code/server/config/server.local.yaml).Path
$runDirectory = Join-Path $PWD "logs/manual/example"

# 分别在不同终端运行；不需要向目录复制进程数量配置。
dotnet build/bin/TGame.Server/debug/TGame.Server.dll Router $runDirectory
dotnet build/bin/TGame.Server/debug/TGame.Server.dll DBMgr $runDirectory
dotnet build/bin/TGame.Server/debug/TGame.Server.dll Base $runDirectory
dotnet build/bin/TGame.Server/debug/TGame.Server.dll Scene $runDirectory
```

每个进程只指定类型；启动多个 Scene 就多次启动 `Scene`。各角色当前只启动进程基础框架，DBMgr、Profile 不初始化存储，不需要数据库凭据。

宿主环境 YAML 只要求 `zooKeeper` 与 `discoveryRoot`，`minimumLogLevel` 可选。MongoDB、Redis 和 Profile 字段不参与基础框架启动校验，独立存储工具使用时自行校验所需字段与凭据。

宿主先创建日志，使用 `ServerSettings.LoadSelected()` 显式加载 YAML，并加载引擎配置，再构建一个 IoC 根容器。ZK、ID 和节点注册为共享服务，依赖通过构造函数传入。ZooKeeper 代理构造不连接，宿主显式初始化会话，用临时节点从 1 开始抢占空闲编号，例如 `/tgame/test/server-Scene1`，随后初始化 ID 生成器并解析节点。只有创建明确返回节点已存在才尝试下一个；创建结果不确定时终止共享会话。编号由 `ServerProcess.FormatName` 格式化，空地址占号节点不参与拨号。

监听启动后持续发现主动目标；每种主动目标类型至少有一个已完成握手的连接后，向已占用的节点发布监听地址并记录 `PROCESS_READY`。依赖根节点（默认 Router）无需等待入站实例，可直接就绪并发布。接收方只接受本地已就绪时的连接，主动方可以尚未发布地址，但必须已占用合法的临时身份。

正常退出先取消并等待后台工作、停止监听，再异步释放容器中的 ID 生成器和 ZooKeeper 会话，最后释放日志；崩溃后由 ZK 在会话过期时删除节点。空闲编号可复用，存活实例不重新编号。编号标识一次运行中的进程实例，不是永久业务身份。会话失效继续停止进程，不能继续使用已失效的编号和雪花 worker 租约。

## 进程连接与就绪

持续发现并尝试连接所有符合主动目标类型的实例。`ServerNode.Ready` 仅要求每种主动目标类型至少有一个完成握手的连接；入站类型不参与该条件，也没有实体初始化或注册确认阶段。

- Base 至少连接一个 Router 和一个 DBMgr，不等待 Gate。
- Scene 至少连接一个 Router。
- Gate 至少连接一个 Login 和一个 Base。
- Router 无主动目标，可直接就绪。

新增 Router2 尚未连接，不会使已有 Router1 的成功连接失效。失去冗余实例时保持就绪；失去某类最后一个可用实例时降为未就绪，持续发现、重连并在握手条件恢复后恢复就绪。`FirstLinks` 只完成一次，不能用它替代当前 `Ready`。

基础 RPC 使用 `ServerNode.CallPeerAsync` 向已连接的实例直接发送请求，保留请求关联、错误、超时和取消。当前未接入业务处理入口，收到请求返回 `Unimplemented`；Router 不执行实体路由，启动就绪也不代表已提供游戏业务。

## ZooKeeper 成员变化

引擎读取完整成员快照并设置 Watch，通知后重新读取和续订。复用 Watcher 并合并通知，避免稳定成员的监听对象累积。记录包含类型、规范实例名、监听地址及节点创建代次；成员离开、地址变更、同名节点重建都会取消旧连接维护并按新快照收敛。非法成员记录被记录并忽略，不能终止其他健康成员的发现。

目前端点仍限本机回环地址；跨机器地址发布不在本次范围。当前框架只处理进程成员与连接变化；后续接入业务时，需另行设计业务状态迁移与排空。

## 控制台启动数量

`code/server/config/processes.json` 仅供控制台决定每种类型启动多少次。必须包含所有类型，数量为非负整数，整组至少一个进程。控制台仍保存本轮启动计划；服务器不读取它。

控制台启动时传类型，按 PID 与启动时间读取实际获配实例名，并按 `ProcessReady`（`PROCESS_READY`）事件判断启动就绪。启动槽位只用于本地进程恢复，不被当作 ZK 身份；日志页签显示实际实例。停止写入精确进程生命周期的标记，避免实例编号复用导致停止错对象。控制台只恢复带有 `dynamic-discovery` 标记的运行组，不再兼容旧静态身份快照。遇到旧组时，先用旧版控制台停止整组，再删除 `logs/tools/server-console/current` 会话指针，重新打开控制台并编译启动。

手动停止可写 `stop-Scene1`（按当前实例）或运行目录的 `stop`（整组）。使用 `stop-Scene1` 后重新使用同一运行目录启动时，应删除已处理的手动停止标记。控制台自己的精确停止标记不影响后来的同名实例。

## 日志和验证

服务器环境 YAML 通过 `minimumLogLevel` 控制本次运行的最低日志级别，支持 `DEBUG`、`INFO`、`ERROR`。本地测试配置 `code/server/config/server.local.yaml` 默认使用 `DEBUG`；其他配置省略此项时使用 `INFO`。

```yaml
minimumLogLevel: DEBUG
```

- `DEBUG`：测试排查所需的请求收发和服务发现明细；独立存储工具可记录缓存读取细节。
- `INFO`：监听、连接建立、初始化及进程就绪等普通运行记录。
- `ERROR`：进程或初始化失败、RPC 异常、连接丢失等需要关注和排查的问题。

日志管理器由宿主在配置加载前通过 `new GameLog()` 创建，将同一个对象注册到 IoC 容器；调用方接收实例后使用 `log.Debug` / `Info` / `Error`。ZooKeeper 占用实例身份后通过 `log.OpenServer(process)` 开启文件日志。这个已有实例由宿主显式释放，容器不接管它的释放；容器构建、启动或清理失败仍可记录日志，最后才关闭日志文件。重复打开文件和释放后的调用会明确报错。

每条 JSON 日志包含大写 `level` 字段。最低级别为 `INFO` 时不写入 DEBUG；为 `ERROR` 时只写入 ERROR。过滤在序列化及写文件前执行，未打开日志文件时的标准输出也使用相同过滤规则。级别由运行配置决定，与 Debug/Release 编译模式无关。启动配置加载失败仍会记录 ERROR。

控制台会保存环境配置快照；修改级别后需“编译并重启”或停止整组后重新启动才能应用。当前控制台依赖 INFO 级别的 `PROCESS_READY` 判断启动就绪，因此最低级别设为 `ERROR` 时无法准确展示就绪状态。

例如 Base2 的日志写入 `logs/server/Base2Server/`，记录中 `role` 为 `Base`，`instance` 为 `Base2`。日志文件以 PID 和进程启动 UTC ticks 定位，不再使用 runId。`stop-Base2` 只停止 Base2，`stop` 停止整组。

以下为当前操作入口，不表示本次文档更新已经执行这些检查。按改动选取必要的小范围检查，避免重复运行同一覆盖范围。

```powershell
# 基础节点、握手、RPC 与就绪检查；--node 与 --engine 同义，无参数也运行 engine。
dotnet run --project code/tests/engine/TGame.EngineTests.csproj -- --engine

# 动态拓扑与真实回环 gRPC，不依赖外部服务。
dotnet run --project code/tests/engine/TGame.EngineTests.csproj -- --dynamic-topology
dotnet run --project code/tests/engine/TGame.EngineTests.csproj -- --discovery-links

# IoC 生命周期、日志与配置；按本次改动选择。
dotnet run --project code/tests/engine/TGame.EngineTests.csproj -- --ioc
dotnet run --project code/tests/engine/TGame.EngineTests.csproj -- --logging
dotnet run --project code/tests/engine/TGame.EngineTests.csproj -- --configuration

# 控制台就绪状态、身份跟踪、恢复和精确停止，不启动服务器组。
dotnet run --project tools/server-console/tests/ServerConsole.Check.csproj -- --state-only
```

外部 ZooKeeper 或完整控制台联调须另行说明范围、预计耗时并获得明确同意；准备本地 SSH 隧道后再运行所需入口：

```powershell
$env:TGAME_SERVER_CONFIG = (Resolve-Path code/server/config/server.local.yaml).Path
dotnet run --project code/tests/engine/TGame.EngineTests.csproj -- --registry
dotnet run --project code/tests/engine/TGame.EngineTests.csproj -- --startup-publication
pwsh -NoProfile -File tools/scripts/powershell/Test-ServerConsole.ps1 -Configuration code/server/config/processes.json
```
