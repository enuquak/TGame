# 云服务器标准连接方式

本项目统一使用本机 OpenSSH 客户端，读取用户级 SSH 配置，通过 `TGame-server` 别名连接。主机地址、登录用户、端口和身份文件由本机配置维护；项目脚本与后续部署命令复用该配置。

## 当前已验证配置

配置文件：`C:\Users\Administrator\.ssh\config`（通用路径：`$env:USERPROFILE\.ssh\config`）。以下为验证时的配置记录；连接参数有变更时以本机配置为准。

```sshconfig
Host TGame-server
    HostName 120.26.35.13
    User root
    Port 22
    IdentityFile C:/Users/Administrator/.ssh/id_ed25519
    IdentitiesOnly yes
    ServerAliveInterval 60
    ServerAliveCountMax 3
```

现有机器已配置密钥和主机信任，无需重新生成或覆盖密钥。其他开发机在自己的 SSH 配置中保留 `TGame-server` 别名，按实际情况设置身份文件和已授权账号；私钥不放入项目目录。

## 日常操作

在项目根目录运行 BAT 入口即可，当前终端可以是 CMD、Windows PowerShell 5.1 或 PowerShell 7；入口始终调用 PowerShell 7。

```powershell
# 只读连接检查：输出登录用户、主机名、内核和系统版本
.\tools\scripts\Connect-Server.bat -Check

# 交互登录，输入 exit 退出远程会话
.\tools\scripts\Connect-Server.bat

# 执行一条远程命令，由远端 Linux shell 解释
pwsh -NoProfile -File .\tools\scripts\powershell\Connect-Server.ps1 -RemoteCommand 'hostname && uptime'
```

脚本明确读取 `$env:USERPROFILE\.ssh\config`，使用 `TGame-server`，启用严格主机密钥校验与 15 秒连接超时。检查和远程命令模式额外启用 `BatchMode=yes`，不等待密码或确认输入；SSH 的退出码原样返回。连接超时仅限制建立连接，不限制远程命令运行时间。

远程命令建议使用 PowerShell 单引号字符串，避免本机提前展开远端的 `$变量`。例如：

```powershell
pwsh -NoProfile -File .\tools\scripts\powershell\Connect-Server.ps1 -RemoteCommand 'echo "$HOME"'
```

需要直接调用 OpenSSH 时使用同一配置与别名：

```powershell
# 交互登录
ssh -F "$env:USERPROFILE\.ssh\config" -o StrictHostKeyChecking=yes TGame-server

# 非交互只读检查
ssh -F "$env:USERPROFILE\.ssh\config" -o BatchMode=yes -o StrictHostKeyChecking=yes -o ConnectTimeout=15 TGame-server 'hostname && whoami'

# 上传文件示例：替换实际本地文件和远端路径后执行
scp -F "$env:USERPROFILE\.ssh\config" -o StrictHostKeyChecking=yes .\<本地文件> TGame-server:/<远端目录>/

# 文件浏览
sftp -F "$env:USERPROFILE\.ssh\config" -o StrictHostKeyChecking=yes TGame-server
```

VS Code Remote - SSH 同样选择 `TGame-server`；若需显式指定配置，`remote.SSH.configFile` 使用 `C:\Users\Administrator\.ssh\config`。

## 基础服务统一使用 SSH 隧道

2026-11-05 确立为项目标准：本机开发程序、GUI、浏览器和 Agent 访问云端数据库、中间件、管理页面及知识服务，统一使用 SSH 隧道，不采用公网 IP 白名单直连。云端 Docker 发布端口和本机转发端口均仅绑定 `127.0.0.1`，云安全组不对公网开放这些服务端口。云端容器之间通过内部服务名互访；玩家公共入口另行规划。

基础 SSH 登录配置只维护主机身份和认证信息；环境转发由项目脚本统一管理。在项目根目录的终端执行：

```powershell
# 后台启动，复用 TGame-server 和严格主机密钥校验
./tools/scripts/Start-EnvironmentTunnel.bat

# 查看或停止当前项目隧道
./tools/scripts/Start-EnvironmentTunnel.bat -Action Status
./tools/scripts/Start-EnvironmentTunnel.bat -Action Stop
```

MongoDB 连接 `127.0.0.1:37017`，Redis 连接 `127.0.0.1:16379`；完整映射见 [环境配置](公众号/技术方案的选型/环境配置.md#52-云端端口映射)，GUI 和浏览器入口见 [环境配置落地记录](环境配置落地记录.md)。新增或调整映射时，同步修改脚本及这些文档。

隧道需在访问期间保持运行，开机后手动启动；断线后先 Stop 再 Start，错误日志在 `logs/tools/environment-tunnel/ssh.log`。不要同时用多个 SSH 进程或 Remote - SSH 转发相同本地端口。隧道进程存在不等于后端服务可用，仍需通过对应客户端验证。OpenViking 采用本机部署，直接访问 `127.0.0.1:1933`。

双击启动请使用 `tools/scripts/Start-EnvironmentTunnel.bat`。它调用 PowerShell 7，并保留成功或失败结果，按任意键后关闭入口窗口，后台 SSH 隧道继续运行。直接用 Windows 默认 5.1 执行要求 7.0 的 `.ps1` 会报 `ScriptRequiresUnmatchedPSVersion`；使用 BAT 可避免版本选错。自动化使用 `pwsh -NoProfile -File ./tools/scripts/powershell/Start-EnvironmentTunnel.ps1`，不等待按键。

## 首次连接与排查

- 新机器首次连接时，先通过云控制台等可信渠道核对主机公钥指纹，再执行 `ssh -F "$env:USERPROFILE\.ssh\config" -o StrictHostKeyChecking=ask TGame-server` 并确认。确认后，标准脚本使用已有的 `known_hosts` 记录进行校验。
- `Host key verification failed`：检查是否尚未建立信任，或服务器密钥发生变化。确认原因与正确指纹后更新对应记录，不关闭主机校验。
- `Permission denied (publickey)`：检查配置中的用户和 `IdentityFile`，以及服务端是否已授权对应公钥。加密私钥用于非交互模式时，需要先由本机 `ssh-agent` 加载。
- 连接超时或拒绝：检查云服务器状态、SSH 服务、安全组和本机网络是否允许访问配置中的端口。
- 查看实际生效的配置：`ssh -F "$env:USERPROFILE\.ssh\config" -G TGame-server`；需要诊断时在连接命令中添加 `-v`。
