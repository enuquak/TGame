# 进程组配置单例

目标：进程启动时加载一次 `processes.json`，引擎通过类型静态入口查询实例、进程类型和成员列表，不再逐层传递 `group`。

## 方案取舍

- 将 `ServerGroup` 本身改为全局对象，会影响控制台独立读取、保存不同运行组的用途。
- 采用独立的 `ServerConfiguration` 服务持有已校验的 `ServerGroup`，保留原数据对象的独立读写。这是针对用户所要求单例方向的实现选择。

## 生命周期与边界

- 配置服务属于 Engine，宿主在创建节点前显式 `Initialize(path)`，用 `using` 在节点和后台任务结束后释放。
- 唯一实例封装在类型内部，只暴露静态查询；未初始化、重复初始化及非法配置直接失败。
- 运行期间使用启动快照，不引入热重载；业务 YAML 和存储配置保持现有归属。
- `ServerNode`、`Topology`、ZooKeeper 注册不再传递配置对象；原 `PeerRole` 使用处改为枚举类型查询。
- 测试同一时刻只运行一个配置生命周期；组内仍可建立多个节点，按原场景验证连接、注册及路由。

验证限于短时编译、配置生命周期、节点和路由内存检查，不启动外部服务或完整测试流程。
