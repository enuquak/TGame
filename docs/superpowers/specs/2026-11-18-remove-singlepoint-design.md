# 移除 SinglePoint，收敛为进程基础框架

用户已选择：保留 ZooKeeper、进程连接、基础通信、日志和 ID，移除依赖 SinglePoint 的实体与业务入口。

## 范围与方案

- 删除 SinglePoint 基类、类型标注、注册器、Router/Profile/DBMgr 子类，以及实体注册、实体路由和相应 RPC 入口。
- 保留进程角色、ZooKeeper 占号和地址发布、动态发现、双向连接、日志单例和雪花 ID。独立的存储工具及共享业务协议不在本次删除范围，但进程启动不再初始化数据库或业务服务。
- 基础宿主配置只要求 ZooKeeper 地址和发现根路径；可选的 Profile 存储字段在独立存储入口启用时校验。
- `ServerNode.Ready` 仅取决于主动依赖连接：每种目标类型至少一条已完成握手的连接；无主动依赖的进程无需等待入站连接。
- 启动依次完成日志、配置、ZooKeeper 占号、ID、监听与依赖连接，最后发布服务地址并发出 `PROCESS_READY`。取消、断线、重连和身份校验继续生效。
- 基础 RPC 保留请求 ID、Any 负载、响应和错误、超时与取消；删除实体目标及转发字段，保留其 Protobuf 字段号和名称。支持按已连接的进程实例直接发送请求；未接入业务处理时返回 `Unimplemented`，不伪造成功。
- 控制台按进程就绪事件判断状态；测试目录和程序集从 SinglePoint 改为 Engine；同步当前规范和使用文档，历史方案保留为历史记录。

替代方案是把现有实体和业务能力迁入新组件；用户选择先移除这些入口，因此本次不引入替代的业务生命周期或路由框架。

## 验证边界

只做编译和短时定向检查：进程握手与就绪、动态连接、基础 RPC、日志及控制台本地状态。外部服务联调和完整测试需另获同意。
