# 服务器组实例数量配置

用户要求：配置本组每种进程类型的总数；连接齐所依赖类型的全部实例后，才完成首次连接任务，随后执行角色初始化。

## 设计

- 将现有 `code/server/config/processes.json` 从角色数组改为角色与非负整数数量的对象。所有 ProcessType 必须显式列出，0 表示本组不启动该类型，至少启动一个进程。
- 沿用 Topology 的连接方向。每条类型关系展开为两类实例之间的所有连接；就绪检查包含本节点的主动和被动连接。没有预期邻居时直接完成首次连接任务。
- 实例编号从 1 开始。为保留现有单实例入口，第一个实例名称仍为 Login，后续为 Login2、Login3；角色与实例名称分开保存。
- 服务发现、握手、连接表、实体归属均以实例名称识别进程。拒绝重复、越界、未配置和不属于拓扑的实例，按预期实例集合检查齐全，不能只比较总数。
- 启动工具把配置复制到运行目录。本组所有进程从该快照读取，运行中编辑源码配置不会改变正在运行的组。控制台恢复时使用该组快照，新一组启动才应用新配置。
- CLI 保持两个参数：实例名称、运行目录。日志分实例目录，增加 instance 字段；停止标记、进程名、控制台标签也区分实例。
- 首次完成后断线不会重置 Task；当前 Ready 随连接丢失变为 false，重连齐全后恢复。Initialized 表示角色初始化完成，不因断线重复初始化。
- 按角色发起的现有业务请求继续使用该角色的第一个实例；实体路由使用精确实例。此次不新增负载均衡、配置热更新或扩缩容协议。

## 取舍

仅改变连接计数无法区分多个进程，也无法实际建立多实例连接，因此同时修改注册、握手和启动入口。复用现有 JSON 文件，避免再建立一份数量配置。复用已提交的 GUID 实体注册改动，避免多个实例注册相同测试实体 ID。

## 验收

Gate 依赖 Login=2、Base=3：少任意一个实例都不能完成 FirstLinks；错误角色、重复实例不得补足计数；全部握手成功后才能开始角色初始化。覆盖取消、断线重连、零邻居、配置错误、控制台按数量展开及独立停止/恢复；回归现有 SinglePoint、联通测试和控制台测试。
