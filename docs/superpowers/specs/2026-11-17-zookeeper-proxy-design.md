# ZooKeeper 统一代理

用户选择代理直接提供现有功能所需的操作：注册进程、查询进程地址、申请 worker ID；删除 ServiceRegistry。

## 方案

- 采用 `ZooKeeperProxy` 进程单例，持有唯一 ZooKeeper 客户端和会话，集中节点读写、监听和临时节点租约。
- 未采用只包装通用 CRUD 的方案：它仍要求服务发现和 ID 模块各自组织 ZK 操作，不符合本次选定的接口边界。
- `SnowflakeIdGenerator` 保留算法，申请和释放 worker 委托代理；保留会话丢失后永久停止发号的保护。

## 生命周期和配置

宿主依次初始化代理、ID 生成器、服务节点；退出按相反顺序释放。初始化失败不发布单例。生命周期由宿主顺序管理，不支持并发初始化和释放。连接断开或会话失效后停止当前进程，不在原会话上重新分配身份。

`zookeeper.json` 声明连接和会话超时；地址与服务发现根路径仍由宿主 ServerSettings 提供。`id-generator.json` 仅保留 worker 根路径。进程节点路径、注册地址校验及重复注册报错保持现有语义。
