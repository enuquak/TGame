# 动态进程发现

用户已在会话确认：启动传类型，通过 ZK 临时节点抢占从 1 开始的实例编号；持续发现并连接全部符合类型配置的实例。每种主动连接目标类型至少有一条完成握手的连接即连接就绪，不等待入站类型。新增或失去冗余实例不影响已有就绪状态，失去某类最后一条可用连接时降为未就绪并继续重连。

## 方案

采用已有临时节点占位与注册机制；不使用数量加一，也不另建分布式锁。启动先以空地址抢占身份，完成主动连接、SinglePoint 初始化和实体注册确认后发布地址；空地址节点不作为可拨号成员。普通 Watch 通过重新读取完整快照并同时布置下一次 Watch 收敛成员变化。快照携带节点创建代次，处理同名实例重启与端口变化。会话失效继续停止进程。

类型连接规则单独保存在 `connections.json`，校验未知类型、自连、双向拨号、Gate 目标及循环依赖。`processes.json` 只供控制台规划启动次数。实例名通过 `ServerProcess.FormatName` 生成；网络输入严格解析类型与正整数编号，不再受本地数量上限限制。网络入站校验已占用临时身份，并要求接收方本地就绪；主动方不必已发布地址。

SinglePoint 仍在引擎连接阶段完成后创建。所有连接都执行实体登记，但初始化只等待每种主动目标至少一个连接确认登记；入站及额外实例不阻塞初始化。新连接在本地实体登记完成后同步身份，连接结束清理路由。

控制台启动参数改为类型，按子进程 PID 和启动时间取得实际分配名称，日志与停止操作使用实际身份；启动槽位不充当运行身份。跨机器监听、自动扩容控制器和业务实体迁移不在范围内。
