# Dynamic process discovery Implementation Plan

> **For agentic workers:** Use superpowers:executing-plans inline; finish with one independent review.

**Goal:** 按类型启动，ZK 抢占身份并持续维护动态连接，以每种主动目标至少一个连接判断就绪。

**Architecture:** 引擎配置只包含类型关系，ZK 保存实际实例与端点。发现循环增删连接维护任务，实体注册跟随连接生命周期。

**Tech Stack:** .NET 10、现有 ZooKeeperNetEx、gRPC、PowerShell 7。

**Spec:** `docs/superpowers/specs/2026-11-18-dynamic-process-discovery-design.md`

## Global Constraints

- 复用当前分支；不覆盖用户改动。
- 引擎不引用业务 Shared；单例静态入口；中文注释与完整花括号。
- 仅小范围短检查，完整测试需另获明确同意。

## Review Focus

- 并发抢号与创建结果不确定：只有明确 NodeExists 才尝试下一编号。
- 同名成员重启、地址变更和漏掉中间 Watch 事件：按快照与创建代次收敛。
- 冗余连接或入站注册迟到不能阻塞就绪；最后一个目标断线后可恢复。
- 初始化与新连接同时发生：不遗漏实体注册，也不重复登记。
- 控制台启动槽位与实际名称不同：仍可读日志、恢复和停止准确的子进程。
