# 通用 RPC 实施计划

设计：[通用 RPC 传输帧](../specs/2026-11-17-transport-rpc-design.md)。基线：main `26b88a4`。在 `codex/transport-rpc` 实施。

- [x] 用协议描述符检查复现传输层依赖业务协议的问题。
- [x] 替换 Frame 的业务字段，增加通用请求、响应及按 Protobuf 类型注册的分发器。
- [x] 迁移 PeerLink、Ping/Pong、Profile 的收发和日志，保留握手、队列与路由行为。
- [x] 迁移既有测试，验证非业务消息也可注册和调用，并覆盖关联编号、错误载荷/类型、取消和断线。
- [x] 运行 SinglePoint 全部检查、默认组及多实例组联通验收，更新结构文档。
- [x] 审查实际改动，确认符合提交与合并条件；按仓库规范提交并合并本地 main。

审查重点：响应串线；同一流嵌套 RPC 死锁；请求编号与载荷不一致；连接关闭后的等待清理；多实例实体归属隔离。

决策：用户已明确要求实施，沿用已有 gRPC、Protobuf 和诊断入口，不引入额外依赖或另行审批流程。整组协议升级需要重启，此限制已经告知。

验证记录：

- RED：协议边界检查在旧代码下明确报错 `Transport must not depend on application protocol pingpong.proto`。
- GREEN：SinglePoint 检查通过，包含通用消息序列化和分发、乱序与未知响应、重复请求、错误响应类型、未知方法、缺少/损坏载荷、请求编号不一致、取消/断线，以及已有握手和多实例归属检查。
- 默认 BAT 验收：8 进程、9 条 gRPC 连接、25 次 Pong、2 次 Mongo 检查、5 次 GM HTTP 检查通过。
- 多实例验收：17 进程、42 条 gRPC 连接、相同业务验收通过。
- Protobuf_Compile 导出入口通过；服务器、探针客户端、控制台构建通过，0 警告/0 错误。
- 最终独立只读审查：无新增 P1/P2 阻塞问题。

保留的既有边界：请求编号应为每次新调用分配的新 GUID，取消/超时后不得复用编号等待迟到响应；请求等待超时仍从写入完成后计时，阻塞写入仍依赖调用/传输取消；每条连接串行处理请求，不扩展到任意双向递归 RPC。上述边界未被本次重构改变，现有调用路径的多进程验收已覆盖。
