# 项目协作约定

## 目录组织

- 游戏源码集中在 `code/`，保持客户端与服务器目录对称；服务器引擎位于 `code/server/engine/`，工具统一按名称放在 `tools/`。
- 目录职责与生成规则以 [项目文件结构](../../docs/项目文件结构.md) 为准。生成代码不手工修改；后续细微结构调整默认只向用户展示 diff。
- 本文中的脚本命令从仓库根目录执行；从 `code/` 工作时先切换到上一级目录。

## Git 事项分支

- 每个独立事项开始前，从最新的 `main` 创建并切换到事项分支，默认命名为 `codex/<事项名>`。同一事项的后续修改继续使用该分支。
- 在事项分支上修改、验证并提交该事项的文件。提交前用 `git status` 和 `git diff --cached` 核对范围。禁止直接在 `main` 上提交改动。
- 事项完成并通过验证后，切回 `main`，执行 `git merge --no-ff <事项分支>` 合入，保留可追溯的合并记录。

## 代码与技能使用

- 默认采用 Ponytail `full`：完成当前需求所需的最小改动，复用现有实现，不提前添加未使用的抽象、配置项或兼容分支。
- 外部输入、权限、协议和存盘边界保留必要校验；内部错误应明确暴露，不用宽泛捕获、默认成功或臆测性 fallback 掩盖问题。
- `ponytail-review` 用于审查实际修改；`deslop` 仅在明确要求清理或审计时使用，默认 audit，不自动开展全仓库删改。
- C# 问题按需使用 `csharp-expert`，Blazor 组件使用 `author-component`；技能中的通用偏好不能覆盖本项目的技术选型、实际需求或必要的可访问性要求。
- 仅在存在性能需求或热点证据时使用 `analyzing-dotnet-performance`、`microbenchmarking`，先测量再优化，不为技能示例引入新的架构或框架。

## 配置与注册

- 同一项配置或映射只在一处声明。所有使用方读取这份声明，需要的索引或注册表由它生成。
- 注册声明优先放在最接近用途的位置。属于某个类型的映射写在该类型声明处，只供某个功能使用的注册可在该功能入口按需完成。
- 例如，Base 与其 SinglePoint 的对应关系只写在类声明上的 `[SinglePointFor(ProcessType.Base)]`。宿主启动时统一收集标注并校验缺失和重复映射。

## Windows 脚本规范

- 所有 `.ps1` 实现和检查脚本集中放在 `tools/scripts/powershell/`，`tools/scripts/` 外层只保留日常 `.bat` 入口。Windows 日常操作统一提供 `.bat` 入口，内部调用 **PowerShell 7（`pwsh.exe`）**；`.ps1` 保存实现逻辑并声明 `#requires -Version 7.0`。
- `.bat` 优先使用 `%ProgramFiles%\PowerShell\7\pwsh.exe`，其次查找 PATH；缺少 PowerShell 7 时显示安装提示，不回退到 Windows PowerShell 5.1。
- `.bat` 支持双击及终端调用，转发参数、保留执行结果并返回原退出码。自动化直接使用 `pwsh.exe -NoProfile -File <脚本.ps1>`，避免等待按键。
- 新增或修改启动脚本须验证 BAT 入口、成功与失败退出码；不要把复杂逻辑或凭据写在 BAT 中。

## 云服务器连接

- 本项目统一通过 OpenSSH 和用户级 SSH 配置中的 `TGame-server` 别名连接云服务器。
- 当前 Windows 配置文件为 `C:\Users\Administrator\.ssh\config`；脚本使用 `$env:USERPROFILE\.ssh\config`。主机地址、用户、端口与私钥路径以该文件为准，不在脚本中重复维护。
- 在项目根目录运行 `./tools/scripts/Connect-Server.bat -Check` 验证连接；交互登录使用 `./tools/scripts/Connect-Server.bat`；执行远程命令使用 `pwsh -NoProfile -File ./tools/scripts/powershell/Connect-Server.ps1 -RemoteCommand '命令'`。
- 自动化连接启用 `BatchMode=yes`、`StrictHostKeyChecking=yes` 和连接超时。保持主机密钥校验，不使用关闭校验的参数绕过连接失败。
- 私钥只保存在本机 SSH 目录，不读取或复制私钥内容到仓库、日志或文档。
- 后续 SSH、SCP、SFTP 和端口转发均复用同一配置与别名；具体命令、首次信任主机及故障排查见 [服务器连接说明](../../docs/服务器连接.md)。

## 云端基础服务访问标准

- 本机开发程序、数据库 GUI、浏览器和 Agent 访问云端数据库、中间件、管理页面及知识服务时，统一使用 SSH 隧道，不采用公网 IP 白名单直连方案。
- 这些服务的 Docker 宿主机发布端口仅绑定 `127.0.0.1`，本机转发端口也仅绑定 `127.0.0.1`；云安全组不对公网开放这些服务端口。
- 在项目根目录的终端运行 `./tools/scripts/Start-EnvironmentTunnel.bat` 启动隧道；查看状态使用 `-Action Status`，停止使用 `-Action Stop`。断线后先停止再启动，避免多个转发进程占用相同端口。
- 本机连接统一使用脚本约定的映射地址：MongoDB 为 `127.0.0.1:37017`，Redis 为 `127.0.0.1:16379`，其余入口见 [环境配置落地记录](../../docs/环境配置落地记录.md)。新增或调整映射时同步更新脚本和相关文档。OpenViking 采用本机部署，直接访问 `127.0.0.1:1933`，不使用云端转发。
- 云端同一 Docker 网络内的服务通过容器服务名和内部端口互访。面向玩家的公共游戏入口另行配置 WSS/HTTPS，不属于上述基础服务访问范围。
