# 项目协作约定

## 目录组织

- 游戏源码集中在 `code/`，保持客户端与服务器目录对称；服务器引擎位于 `code/server/engine/`，工具统一按名称放在 `tools/`。
- 进程拓扑、连接接入与生命周期、服务发现、基础通信、日志和 ID 属于 `server/engine/`；独立存储与业务逻辑属于 `server/logic/`。`server/app/` 负责启动、配置和组装。`shared/` 仅承载业务共享协议、类型与数据；通用通信协议、进程配置、ID 校验和日志基础设施由 Engine 自己维护。Engine 不得引用业务 Shared、宿主或具体业务实现；业务 Shared 也不引用服务器引擎。宿主显式引用 Engine 与 Shared，以独立引擎编译和程序集边界检查验证分层。
- 引擎协议在 `server/engine/protocols/` 定义并生成到引擎的 `generated/protocols/`；业务协议在 `shared/protocols/` 定义并生成到共享项目的 `generated/protocols/`。日志事件、环境变量等混合声明按职责拆分，业务项不得随基础设施迁入引擎。现有进程角色体系保留，`ProcessType` 与实例命名统一归属引擎。
- 当前服务器运行进程基础框架，不创建实体、不登记实体归属、不执行实体路由，也不在启动时初始化 DBMgr/Profile 业务。独立存储工具和共享业务协议保留，由各自使用方按需调用。
- 启动依次完成日志初始化、配置加载、ZooKeeper 会话与空地址临时占号、ID 初始化、监听及依赖连接，最后发布可发现的服务地址并记录 `PROCESS_READY`。引擎持续发现并主动连接已发布地址的依赖进程，`ServerNode.Ready` 仅要求每种主动目标类型至少一个已完成握手的连接；无主动依赖时可直接就绪，不等待入站连接。握手只交换进程身份。主动连接依赖必须无环，配置加载时拒绝循环依赖；入站接收端必须已就绪，连接方身份只要求有效临时占号，不要求已发布地址。失去某类最后一条依赖连接时撤销当前就绪，重连握手后恢复；取消、断线和身份校验继续生效。
- 基础 RPC 通过 `CallPeerAsync` 向已连接的进程实例发送请求，保留请求 ID、`Any` 负载、响应、错误、超时和取消。未接入业务处理时返回 `Unimplemented`，不伪造成功；不加入实体目标或转发字段。
- 目录职责与生成规则以 [项目文件结构](../../docs/项目文件结构.md) 为准。生成代码不手工修改；后续细微结构调整默认只向用户展示 diff。
- 本文中的脚本命令从仓库根目录执行；从 `code/` 工作时先切换到上一级目录。

## Git 事项分支

- 当前会话已经在非 `main` 分支时，直接复用当前分支，不必为新事项另建分支。当前在 `main` 时，从最新的 `main` 创建并切换到事项分支，默认命名为 `codex/<事项名>`。
- 在事项分支上修改、验证并提交该事项的文件。提交前用 `git status` 和 `git diff --cached` 核对范围。禁止直接在 `main` 上提交改动。
- 独立事项分支完成并通过验证后，切回 `main`，执行 `git merge --no-ff <事项分支>` 合入，保留可追溯的合并记录。复用已有非 `main` 分支时，遵循该分支整体的整合安排，不因单个子事项完成自动合入其他尚未整合的改动。

## 代码与技能使用

- 默认采用 Ponytail `full`：完成当前需求所需的最小改动，复用现有实现，不提前添加未使用的抽象、配置项或兼容分支。
- 外部输入、权限、协议和存盘边界保留必要校验；内部错误应明确暴露，不用宽泛捕获、默认成功或臆测性 fallback 掩盖问题。
- `ponytail-review` 用于审查实际修改；`deslop` 仅在明确要求清理或审计时使用，默认 audit，不自动开展全仓库删改。
- C# 问题按需使用 `csharp-expert`，Blazor 组件使用 `author-component`；技能中的通用偏好不能覆盖本项目的技术选型、实际需求或必要的可访问性要求。
- 仅在存在性能需求或热点证据时使用 `analyzing-dotnet-performance`、`microbenchmarking`，先测量再优化，不为技能示例引入新的架构或框架。

## 验证范围

- 默认只做与本次改动直接相关、耗时较短的必要检查，按需编译或运行小范围测试；文档和格式调整通常只检查 diff，不机械运行测试。
- 完整测试流程或耗时较长的测试，必须先向用户说明验证范围与预计耗时，并获得明确同意后才能执行；代码修改或分支整合的授权不等于这类测试的授权。
- 不为本次任务堆叠验证逻辑，也不无故扩大或重复测试。已有检查通过后，只有新增改动、失败结果或具体疑点才需要追加针对性检查。
- 本文其他条款要求的验证也受此范围约束；需要完整或耗时测试但尚未获同意时，说明未验证的范围，不宣称已通过。

## 代码可读性

- 代码注释尽量使用中文，代码标识符和必要的英文术语保留原文。
- C# 等使用花括号表示代码块的语言中，`if`、`else if`、`else`、`for`、`foreach`、`while`、`do`、`using`、`lock` 等控制语句的语句体必须使用完整花括号，即使只有一条语句也不能省略；`else if` 链保持语言的常规写法。花括号和语句展开到独立行，`using var` 声明不属于需要补块的控制语句。
- 按逻辑段落组织代码，在参数校验、准备数据、执行操作、返回结果等阶段之间适当留一个空行；方法之间、独立代码块之间也应留空行，不机械地在每条语句之间插入空行。
- 优先使用 early return（提前返回）：先处理无效输入、无需继续处理或失败的情况，让正常流程保持较少的嵌套。能够提前返回时，不再用 `else` 包裹后续正常流程；需要暴露的错误仍应明确抛出。
- 一个代码块包含多条语句时展开书写，避免把赋值、调用、`return` 或 `throw` 挤在同一行；简单属性和表达式方法可以保持简洁。
- 控制单条语句的复杂度，不把复合条件、类型判断和三元赋值挤在一条语句里。复合或嵌套的三元表达式应拆成语义清晰的中间变量或完整的 `if / else` 分支；简单的单条件三元表达式可以保留。拆分时保留短路求值、执行顺序和副作用，不为压缩行数牺牲可读性。
- 同一判断表达式包含超过两个 `||` 时，按条件逐行展开，每个由 `||` 分隔的条件独占一行，`||` 保留在上一条件的行尾，后续条件对齐。`if` 判断的首个条件紧随 `if (`，右括号放在最后一个条件之后。保留原有括号分组、条件顺序和短路求值，不为换行提前计算所有条件。
- 链式表达式涉及筛选、排序、选取结果、判空或抛出异常等多个阶段时，按步骤拆成有明确名称的变量、循环和独立条件分支；不要把这些阶段压进一条 `return` 语句。单个简单查询可以保留，不要求把所有 LINQ 调用改成循环。
- 同一逻辑段落内，相邻变量声明在互不依赖且可安全交换的前提下，建议按变量名前声明前缀（类型及修饰词，不计行首缩进）的文本长度从短到长排序，例如 `var` 在 `using var` 前；长度相同时保持原有顺序。不得为排序跨越逻辑段落、改变初始化的副作用或异常行为，也不得改变资源的生命周期和释放顺序。
- 可读性调整应保留原有行为、校验、异常处理和资源释放，不为减少嵌套引入重复逻辑或不必要的抽象。

## 状态与派生属性

- 同一事实只保留一个权威数据来源。能够从已持有数据低成本、无副作用推导的值，使用计算属性、方法或直接读取，不另设字段或自动属性重复存储；例如已有 `type` 时使用 `public string Role => type.ToString();`，不在构造函数中另行赋值 `Role`。
- 已持有完整的身份或配置对象时，优先从该对象读取成员，不再拆出多份派生状态。例如保留 `ServerProcess process` 后，使用 `Name => process.Name`、`Role => process.Role` 和 `process.Type`；已持有连接配置时，廉价的目标类型查询直接从配置取得，不再保存同一列表引用。
- 计算属性应保持轻量、无副作用。改为即时计算时，必须保留原有的快照、对象身份、异常、并发和生命周期语义，不把创建资源、网络访问等操作藏入 getter，也不在每次读取时创建本应共享的任务或对象。
- 有明确用途的性能缓存、查询索引及历史快照可以保留；缓存应有清晰的更新或失效规则，不能仅为可能的性能收益重复保存数据。例如 `ServerGroup.byName` 是按名称查找的索引，不因其可从进程列表重建就直接删除。
- 具有独立语义的生命周期、历史或并发协调状态应保留，不能用不等价的派生条件替代。例如 `linksReady` 用于比较就绪状态变化；`ZooKeeperProxy.initialized` 表示初始化已成功，不能用 `zk != null` 替代，因为客户端已创建不等于握手已完成。

## 命名约定

- 进程名和类名统一使用大写驼峰命名法（PascalCase），每个单词首字母大写，单词之间直接相连，例如进程类型名 `Base`、类名 `ServerNode`。
- 名称中包含已确定的进程缩写时沿用其大小写，例如进程类型 `GM`、`DBMgr`。

- 进程类型名与实例名分开：实例名统一为“类型名 + 从 1 开始的编号”，首个或唯一实例也保留 `1`，例如 `Router1`、`Router2`。实例名由引擎的 `ServerProcess.FormatName` 生成，不在各调用方重复拼接规则。

## 配置与注册

- 禁止在使用处硬编码进程类型、业务状态、协议标识等具有明确含义的字符串或数字，必须引用具名常量或枚举。已有定义时直接复用，不再维护一套相同含义的常量；例如进程角色判断使用 `processType == ProcessType.Gate`，需要字符串标识时引用 `nameof(ProcessType.Gate)`。
- 超时、容量等固定规则使用具名常量；需要按环境或运行情况调整的参数从统一配置读取，不以抽取常量代替配置管理。
- 同一项配置或映射只在一处声明。所有使用方读取这份声明，需要的索引或注册表由它生成。
- 注册声明优先放在最接近用途的位置。属于某个类型的映射写在该类型声明处，只供某个功能使用的注册可在该功能入口按需完成。
- 当前进程类型由 `ProcessType` 声明，主动连接关系从 `connections.json` 读取；`processes.json` 仅供控制台决定启动数量。不要为现有角色建立额外的业务类型注册表或默认业务实现。

## 单例调用

- App 使用 .NET 内置依赖注入建立单个根容器，统一注册进程级的 `ZooKeeperProxy`、`IdGenerator`、`ServerNode` 等共享服务。使用方通过构造函数接收具体依赖，调用实例方法，例如 `zooKeeper.RegisterProcessAsync(...)`、`zooKeeper.SessionLost` 和 `ids.GenId()`；不通过静态 `Instance`、`Current` 或全局 `IServiceProvider` 获取服务。不为注入本身增加无必要的接口或包装器。
- 对象创建与异步初始化分开。ZooKeeper 构造函数不建立连接；App 显式等待连接、认领进程身份，再初始化 ID、解析节点并启动监听及依赖连接。保留初始化状态校验、异常传播和同步保护；容器单例不自动保证服务线程安全。
- 先取消并等待后台工作、停止监听，再异步释放容器，确保 ID worker 租约先于 ZooKeeper 会话释放。由容器创建的共享服务由容器释放，使用方不得自行释放依赖。日志为明确例外：App 在配置加载前创建唯一 `GameLog`，将已有实例注册到容器，并在启动或清理失败已记录后最后显式释放，保证容器构建失败时仍有日志。
- `ServerSettings.LoadSelected()` 与 `ServerConfiguration.Load(...)` 显式加载并校验独立配置实例，通过参数或构造函数传入使用方；运行期间按只读配置使用，不保留全局配置状态。`ServerConfiguration` 同时提供类型连接查询；宿主配置不得进入 Engine。认领完成的 `ServerProcess` 作为不可变身份共享，不增加进程管理器。
- 纯工具、常量及枚举保留静态定义。`PeerLink` 按连接创建，`ZooKeeperSession`、worker 租约及雪花序列仍由所属服务持有，不分别提升为进程单例。未接入启动的存储工具显式接收所需配置、ID 和日志，不因依赖注入恢复业务入口。

## Windows 脚本规范

- 所有 `.ps1` 实现和检查脚本集中放在 `tools/scripts/powershell/`，`tools/scripts/` 外层只保留日常 `.bat` 入口。Windows 日常操作统一提供 `.bat` 入口，内部调用 **PowerShell 7（`pwsh.exe`）**；`.ps1` 保存实现逻辑并声明 `#requires -Version 7.0`。
- `.bat` 优先使用 `%ProgramFiles%\PowerShell\7\pwsh.exe`，其次查找 PATH；缺少 PowerShell 7 时显示安装提示，不回退到 Windows PowerShell 5.1。
- `.bat` 支持双击及终端调用，转发参数、保留执行结果并返回原退出码。自动化直接使用 `pwsh.exe -NoProfile -File <脚本.ps1>`，避免等待按键。
- 新增或修改启动脚本须验证 BAT 入口、成功与失败退出码；不要把复杂逻辑或凭据写在 BAT 中。

## 云服务器连接

- 本项目统一通过 OpenSSH 和用户级 SSH 配置中的 `TGame-server` 别名连接云服务器。
- 当前 Windows 配置文件为 `C:\Users\Administrator\.ssh\config`；脚本使用 `$env:USERPROFILE\.ssh\config`。主机地址、用户、端口与私钥路径以该文件为准，不在脚本中重复维护。
- 在项目根目录运行 `./tools/scripts/Connect-Server.bat -Check` 验证连接；交互登录使用 `./tools/scripts/Connect-Server.bat`；执行远程命令使用 `pwsh -NoProfile -File ./tools/scripts/powershell/Connect-Server.ps1 -RemoteCommand '命令'`。
- 自动化连接启用 `BatchMode=yes`、`StrictHostKeyChecking=yes` 和连接超时。保持主机密钥校验，不使用关闭校验的参数绕过连接失败。
- 私钥只保存在本机 SSH 目录，不读取或复制私钥内容到仓库、日志或文档。
- 后续 SSH、SCP、SFTP 和端口转发均复用同一配置与别名；具体命令、首次信任主机及故障排查见 [服务器连接说明](../../docs/服务器连接.md)。

## 云端基础服务访问标准

- 本机开发程序、数据库 GUI、浏览器和 Agent 访问云端数据库、中间件、管理页面及知识服务时，统一使用 SSH 隧道，不采用公网 IP 白名单直连方案。
- 这些服务的 Docker 宿主机发布端口仅绑定 `127.0.0.1`，本机转发端口也仅绑定 `127.0.0.1`；云安全组不对公网开放这些服务端口。
- 在项目根目录的终端运行 `./tools/scripts/Start-EnvironmentTunnel.bat` 启动隧道；查看状态使用 `-Action Status`，停止使用 `-Action Stop`。断线后先停止再启动，避免多个转发进程占用相同端口。
- 本机连接统一使用脚本约定的映射地址：MongoDB 为 `127.0.0.1:37017`，Redis 为 `127.0.0.1:16379`，其余入口见 [环境配置落地记录](../../docs/环境配置落地记录.md)。新增或调整映射时同步更新脚本和相关文档。OpenViking 采用本机部署，直接访问 `127.0.0.1:1933`，不使用云端转发。
- 云端同一 Docker 网络内的服务通过容器服务名和内部端口互访。面向玩家的公共游戏入口另行配置 WSS/HTTPS，不属于上述基础服务访问范围。
