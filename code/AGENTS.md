# 源码协作入口

开始工作前，必须读取并遵守 [项目协作规范](agents/项目协作规范.md)，该规范适用于整个仓库。

当前会话已在非 `main` 分支时，直接在该分支继续开发，不必为新事项另建分支；当前在 `main` 时先创建[事项分支](agents/项目协作规范.md#git-事项分支)。在事项分支上提交，按该分支的整合安排合并回 `main`。

验证遵循[验证范围](agents/项目协作规范.md#验证范围)：默认只做必要、耗时较短的小范围检查；完整测试流程或耗时较长的测试，必须先说明范围与预计耗时并获得用户明确同意，不无故追加或重复验证。

进程名和类名遵循[命名约定](agents/项目协作规范.md#命名约定)。新增配置或类型映射时，遵循[配置与注册](agents/项目协作规范.md#配置与注册)约定。

进程实例统一使用“类型名 + 从 1 开始的编号”，首个或唯一实例也必须保留编号，例如 `Router1`、`Router2`；类型名仍为 `Router`，实例名通过引擎的 `ServerProcess.FormatName` 统一生成。

进程类型等业务标识必须引用已有常量或枚举，禁止在使用处硬编码；可变参数统一从配置读取。

进程拓扑、连接管理、服务发现及 SinglePoint 基类、默认实现与生命周期放在 `server/engine/`；可选的业务 SinglePoint 子类与业务消息处理放在 `server/logic/`。先完成引擎初始化，再创建并初始化 SinglePoint；未注册业务实现时使用引擎默认类。`shared/` 仅承载业务共享协议、类型与数据；引擎协议和基础类型归属 Engine，引擎不得引用业务 Shared、宿主或业务实现。`app` 显式引用 Engine 与 Shared，负责启动与组装。

代码按[可读性约定](agents/项目协作规范.md#代码可读性)组织：控制语句即使只有一条语句也要使用完整花括号；逻辑段落之间适当留空行，优先使用 early return 减少嵌套；复杂条件与赋值拆开书写，避免复合或嵌套三元表达式，多阶段链式表达式按步骤展开；超过两个 `||` 的判断每个条件独占一行，`||` 放在行尾，后续条件对齐；无依赖且可安全交换的相邻变量声明，建议按声明前缀长度从短到长排序。

代码注释尽量使用中文，代码标识符和必要的英文术语保留原文。

目录职责与生成规则见 [项目文件结构](../docs/项目文件结构.md)。保持 `client/`、`server/` 对称；业务改动按需涉及 `shared/` 和 `tests/`。`generated/` 中的代码由源定义生成，不手工修改。

本目录是 Codex 日常工作目录。项目工具位于 `../tools/`，策划源文件位于 `../design/`；需要开发工具、导出或排查资源时按需访问。文档中注明“项目根目录”的命令，应从本目录的上一级运行。
